# Контрольные вопросы для проверки RAG по Telegram-дампу

Источник набора: stage `chatdb`, таблицы `rag_documents` и `rag_chunks`.

Поля источников ниже используют `rag_documents.external_id`, то есть ID сообщения из Telegram-дампа. Набор подобран так, чтобы проверять не только поиск по ключевым словам, но и способность ответа собрать позицию автора из нескольких связанных постов.

Важно не свести ответ к банальному «нужен хороший UX», а передать мысль про человеческое восприятие и эмоциональность. | `4`, 2022-03-15 |

## Как использовать набор

Для каждого вопроса проверяйте три вещи:

1. Ответ должен опираться на указанные источники, а не на общие рассуждения модели
2. Ответ должен сохранять позицию автора, включая оговорки и причинно-следственные связи
3. Если RAG нашёл нерелевантные фрагменты, ответ должен явно не делать выводов из них

## Признаки хорошего прохождения

| Проверка | Что считать успешным результатом |
|-|-|
| Поиск | В debug-панели RAG среди найденных фрагментов есть хотя бы один из ожидаемых `external_id` |
| Ответ | Ответ содержит ключевые тезисы из колонки «Ожидание от ответа» |
| Источники | Ответ не подменяет источники похожими постами без нужных тезисов |
| Осторожность | Если источники найдены частично, ответ сообщает об ограничении, а не достраивает уверенную фантазию |

  - `backend`: `npx tsc --noEmit`

# Команды

## Координаты проекта

- Корень репозитория на сервере: `/srv/ai-chalange`
- Директория проекта: `/srv/ai-chalange/first-lesson`
- Скрипт деплоя: `/srv/ai-chalange/update.sh`
- Ветка: `develop`

## Порты

| Сервис | Внутренний | Внешний |
| --- | --- | --- |
| Backend | `3000` | `6500` |
| Frontend | `3000` | `6501` |

## URL

- Frontend: `http://167.235.226.104:6501`
- API backend: `http://167.235.226.104:6500/api`

## Локальный процесс

1. Выполни `git status`.
2. Если нужно задеплоить локальные изменения, создай обычное сообщение коммита сам, если только пользователь явно не попросил контролировать его вручную.
3. Запусти проверки компиляции для `backend` и `frontend`.
4. Выполни `git push origin develop`.

## Удалённый процесс

1. Подключись к серверу.
2. Если были добавлены новые env-переменные, проверь и обнови `/srv/ai-chalange/first-lesson/.env`.
3. Выполни:

```bash
cd /srv/ai-chalange
bash update.sh first-lesson
```

## Заметки по деплою

- `.env` игнорируется git, поэтому при появлении новых переменных его нужно обновлять на сервере вручную.
- `ADMIN_PASSWORD_HASH` в серверном `.env` использует экранирование `$$` для `docker-compose`.
- Ожидается, что `update.sh` делает следующее:
  1. `git pull --ff-only`
  2. `docker compose down`
  3. `docker compose up -d --build`
  4. `docker compose ps`

# Проверка

- После деплоя повторно проверь `docker compose ps` и сообщи состояния контейнеров.
- Проверь `docker compose logs --tail=20 backend` и вынеси наружу ошибки или предупреждения.
- Если есть возможность, проверь, что:
  - frontend отвечает на `http://167.235.226.104:6501`
  - backend отвечает на `http://167.235.226.104:6500/api`

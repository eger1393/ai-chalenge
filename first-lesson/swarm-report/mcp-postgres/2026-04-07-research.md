# Research: MCP PostgreSQL в Docker Compose

## Задача
Добавить Docker-контейнер с MCP-сервером для read-only доступа к PostgreSQL (chatdb). Пользователи в чате смогут запрашивать данные из БД — AI решает когда обратиться к БД, или пользователь явно просит.

## Консилиум — сводка

### Архитектор
- Docker: 3 сервиса (postgres, backend, frontend) в `app-network`
- PostgreSQL: `chatuser:chatpass@postgres:5432/chatdb`, порт не проброшен
- `.mcp.json`: только `claude-in-chrome`
- Нет healthcheck у PostgreSQL
- Образ `mcp/postgres` доступен на Docker Hub

### Фронтенд-эксперт
- Фронтенд не имеет отношения к MCP
- Изменений в `.env` фронтенда не требуется
- Но потребуется UI для отображения tool calls в чате

### UI-дизайнер
- Инфраструктурная часть не требует UI
- Но если AI использует function calling — нужно отображать tool usage в message bubble

## Архитектура pipeline (текущая)
- 3 шага: planning → execution → validation
- OpenAI SDK, streaming, **без function calling**
- Для интеграции MCP как tool нужно добавить function calling в execution step

## Ключевые решения
1. MCP как постоянный сервис в docker-compose (SSE через supergateway)
2. Read-only: отдельный PG-пользователь `chatreader` с правами SELECT
3. Backend: новый модуль для коммуникации с MCP
4. OpenAI function calling: tool `query_database` в execution step
5. Frontend: отображение tool calls в pipeline UI

# Спецификация: GitHub Explorer MCP Server

**Дата:** 2026-04-07
**Статус:** Draft
**Feature slug:** github-explorer-mcp

---

## 1. Постановка задачи

Реализовать MCP-сервер для работы с публичными GitHub-репозиториями. Сервер предоставляет LLM (на бэкенде) набор тулов для поиска репозиториев, получения описания, списка веток и истории коммитов.

### Контекст использования

- MCP-сервер развёрнут **на сервере** рядом с основным бэкендом (Nest.js), в **отдельном Docker-контейнере** внутри существующего docker-compose
- **Потребитель тулов — LLM** (Claude/OpenAI) на бэкенде, не пользователь напрямую. LLM решает когда и какой тул вызвать в ходе диалога с пользователем чата
- Бэкенд подключается к MCP через существующий `McpRegistryService` с транспортом **Streamable HTTP**
- Регистрация через `mcp-servers.json` с именем **`github-explorer`**

## 2. Тулы (API Surface)

### 2.1 `search_repos` — Поиск репозиториев по ключевым словам

**Параметры:**
| Параметр | Тип | Обязательный | Описание |
|----------|------|--------------|----------|
| query | string | да | Текстовый запрос для поиска |

**Поведение:**
- Использует GitHub Search API (`GET /search/repositories`)
- Сортировка: **best match** (захардкожена)
- Возвращает **топ-10** результатов (одна страница, `per_page=10`)
- Формат ответа: **JSON**

**Поля в ответе (на каждый репозиторий):**
- `name` — имя репозитория
- `full_name` — owner/repo
- `description` — описание (может быть null)
- `stars` — количество звёзд
- `language` — основной язык (может быть null)
- `url` — HTML URL репозитория

---

### 2.2 `get_description` — Описание конкретного репозитория

**Параметры:**
| Параметр | Тип | Обязательный | Описание |
|----------|------|--------------|----------|
| repository | string | да | owner/repo или полный GitHub URL |

**Поведение:**
- Использует GitHub API (`GET /repos/{owner}/{repo}`)
- Парсит полный URL (https://github.com/owner/repo) если передан вместо owner/repo
- Формат ответа: **JSON**

**Поля в ответе:**
- `name`, `full_name`
- `description` (может быть null)
- `stars`, `language`, `url`

---

### 2.3 `list_branches` — Список веток репозитория

**Параметры:**
| Параметр | Тип | Обязательный | Описание |
|----------|------|--------------|----------|
| repository | string | да | owner/repo или полный GitHub URL |

**Поведение:**
- Использует GitHub API (`GET /repos/{owner}/{repo}/branches`)
- Формат ответа: **JSON**

**Поля в ответе (на каждую ветку):**
- `name` — имя ветки
- `sha` — SHA последнего коммита

---

### 2.4 `get_commits` — Последние коммиты для ветки

**Параметры:**
| Параметр | Тип | Обязательный | По умолчанию | Описание |
|----------|------|--------------|--------------|----------|
| repository | string | да | — | owner/repo или полный GitHub URL |
| branch | string | нет | основная ветка репо | Имя ветки |
| limit | number | нет | 100 | Количество коммитов (1–100) |

**Поведение:**
- Использует GitHub API (`GET /repos/{owner}/{repo}/commits?sha={branch}&per_page={limit}`)
- Если branch не указан — GitHub API использует default branch репозитория
- Формат ответа: **JSON**

**Поля в ответе (на каждый коммит):**
- `sha` — полный SHA коммита
- `message` — сообщение коммита
- `date` — дата коммита
- `author` — имя автора

## 3. Решения по дизайну

| Решение | Выбор | Обоснование |
|---------|-------|-------------|
| Аутентификация GitHub | **Без токена** (анонимный доступ) | Осознанный компромисс — малая нагрузка, 60 req/h достаточно |
| Стек MCP-сервера | **Node.js + TypeScript** | Совпадает с основным стеком проекта |
| Транспорт | **Streamable HTTP** | Уже используется для postgres MCP |
| Количество тулов | **4 отдельных** | Гранулярность: LLM выбирает конкретный тул, а не action-параметр |
| Входной формат репо | **Одна строка** `owner/repo` | Проще для LLM, + парсинг полного URL |
| Формат ответов | **JSON** (не markdown/text) | LLM лучше парсит структуры, сам форматирует для пользователя |
| Сортировка поиска | **Best match** (захардкожена) | Упрощение, один параметр query |
| Фильтры поиска | **Только query** | LLM может сам вставить квалификаторы в строку поиска (language:X и т.д.) |
| Деплой | **В существующий docker-compose** | Единый стек, общая сеть |

## 4. Обработка ошибок

### 4.1 Rate Limit (HTTP 403/429)
- Возвращать **человеко-читаемое сообщение** с указанием времени до сброса лимита (из заголовка `X-RateLimit-Reset`)
- Формат: `"GitHub API rate limit exceeded. Limit resets at {HH:MM UTC}. Anonymous access allows 60 requests/hour."`

### 4.2 Репозиторий / ветка не найден (HTTP 404)
- Возвращать **понятное сообщение**: `"Repository '{repository}' not found or is private. Note: this MCP server only has access to public repositories."`
- Для веток: `"Branch '{branch}' not found in repository '{repository}'."`

### 4.3 Невалидный формат repository
- Если строка не матчит `owner/repo` и не является валидным GitHub URL — возвращать ошибку: `"Invalid repository format. Expected 'owner/repo' or a GitHub URL (https://github.com/owner/repo)."`

### 4.4 Невалидный limit
- Если limit < 1 или > 100 — clamping до [1, 100] с предупреждением в ответе

## 5. Риски

| Риск | Вероятность | Влияние | Митигация |
|------|-------------|---------|-----------|
| **Исчерпание rate limit** (60 req/h на всех пользователей) | Средняя | Высокое — все тулы перестают работать до сброса | Малая нагрузка — осознанный компромисс. При росте нагрузки — добавить токен или кэш |
| **Приватные репо возвращают 404** — пользователь думает что репо не существует | Средняя | Низкое | Сообщение об ошибке явно указывает "not found OR private" |
| **Большой payload коммитов** съедает контекстное окно LLM | Низкая (краткий формат) | Среднее | Краткий формат (hash+msg+date+author), настраиваемый limit |
| **GitHub API downtime** | Низкая | Высокое | Человеко-читаемое сообщение об ошибке, LLM объяснит пользователю |
| **LLM передаёт невалидные параметры** (пустой query, несуществующий owner) | Средняя | Низкое | Валидация на уровне MCP + понятные ошибки |
| **Парсинг URL ломается на нестандартных GitHub URL** (github.com/owner/repo/tree/branch) | Низкая | Низкое | Парсить только `github.com/{owner}/{repo}`, игнорировать trailing path segments |

## 6. Edge Cases

1. **Репозиторий без описания** — `description` = null, тул должен вернуть null/пустую строку, не падать
2. **Пустой результат поиска** — запрос не нашёл ничего: вернуть пустой массив, не ошибку
3. **Репозиторий с 0 коммитов** (пустой репо) — вернуть пустой массив коммитов
4. **Ветка с `/` в имени** (feature/my-branch) — корректно передавать в GitHub API (URL encoding)
5. **Очень длинный query** — GitHub API имеет лимит на длину запроса, прокинуть ошибку GitHub как есть
6. **Одновременные запросы** от нескольких пользователей чата — все идут в один пул 60 req/h, без очередей
7. **GitHub URL с trailing slash** (https://github.com/owner/repo/) — парсить корректно
8. **owner/repo с пробелами или спецсимволами** — валидировать формат перед запросом
9. **Коммиты в default branch при отсутствии параметра branch** — не передавать `sha` параметр вообще, GitHub вернёт default
10. **limit = 0** — clamping до 1

## 7. Definition of Done

### Функциональные критерии
- [ ] MCP-сервер запускается как отдельный Docker-контейнер
- [ ] Сервер доступен по Streamable HTTP транспорту
- [ ] Сервер зарегистрирован в `mcp-servers.json` как `github-explorer`
- [ ] `McpRegistryService` успешно обнаруживает все 4 тула при старте
- [ ] Тул `search_repos` — возвращает топ-10 результатов по query
- [ ] Тул `get_description` — возвращает описание репозитория по owner/repo
- [ ] Тул `list_branches` — возвращает список веток по owner/repo
- [ ] Тул `get_commits` — возвращает коммиты для указанной ветки с настраиваемым limit
- [ ] Все тулы принимают полный GitHub URL и корректно парсят owner/repo из него
- [ ] Все тулы возвращают JSON
- [ ] Все ошибки (404, 429, невалидный ввод) возвращают человеко-читаемые сообщения

### Инфраструктурные критерии
- [ ] Dockerfile для MCP-сервера
- [ ] Сервис добавлен в существующий docker-compose
- [ ] Переменная окружения `MCP_GITHUB_EXPLORER_URL` (или аналог) в mcp-servers.json

### Интеграционные критерии
- [ ] LLM на бэкенде видит тулы с префиксом `github-explorer__`
- [ ] LLM может успешно вызвать каждый из 4 тулов через чат
- [ ] Ошибки rate limit и 404 корректно отображаются пользователю через LLM

## 8. Вне скоупа (явно исключено)

- Аутентификация через GitHub токен
- Кэширование ответов GitHub API
- Пагинация в поиске (больше 10 результатов)
- Расширенные поля в ответах (forks, issues, license, topics)
- Сортировка поиска (stars, forks, updated)
- Расширенные фильтры поиска (language, min_stars)
- Список изменённых файлов в коммитах
- Работа с приватными репозиториями
- Rate limit retry/backoff на уровне MCP

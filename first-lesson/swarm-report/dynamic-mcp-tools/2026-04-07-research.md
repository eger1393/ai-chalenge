# Research: Динамическое обнаружение MCP-инструментов

Дата: 2026-04-07

## Задача
AI в приложении должна динамически получать список доступных тулов от всех MCP серверов и использовать их через OpenAI function calling. Сейчас 1 MCP сервер (postgres-mcp), но будет больше.

## Скоуп
- **Полный стек**: бэкенд + фронтенд
- **Конфигурация**: JSON файл (`mcp-servers.json`)

---

## Архитектор

### Ключевые решения
- Разделить `McpClientService` на 3 слоя: `McpConnection` (одно подключение), `McpRegistry` (реестр + listTools()), `McpToolRouter` (роутинг tool_call)
- **Prefix-based namespace** (`postgres__query`) — двойное подчеркивание как разделитель, совместимо с OpenAI regex `^[a-zA-Z0-9_-]{1,64}$`
- JSON конфиг `backend/mcp-servers.json` с подстановкой env-переменных

### Риски
- Конфликт имён тулов (критический) → решается prefix
- Раздувание tool list (средний) → мониторить количество тулов
- Race condition в ensureConnected() → заменить busy-wait на Promise-based lock

### Затронутые файлы
- `backend/src/mcp/mcp-client.service.ts` → рефакторинг в McpConnection
- `backend/src/mcp/mcp.module.ts` → новые providers
- `backend/src/message-processing/services/step-runner.service.ts` → удаление хардкода DB_TOOLS, интеграция с registry
- Новые файлы: `mcp-registry.service.ts`, `mcp-tool-router.service.ts`, `mcp-servers.json`

## Фронтенд-эксперт

### Текущее состояние
- Фронтенд **уже generic**: хук `use-pipeline.ts` и типы `ToolCallData` не привязаны к конкретным тулам
- Единственный хардкод: `TOOL_LABELS` и иконка `Database` в `pipeline-message-bubble.tsx`

### Рекомендации
- Добавить поле `server` в SSE event `tool_call`
- Расширить `TOOL_LABELS` или получать label с бэкенда
- Эндпоинт `GET /mcp/status` — для индикатора серверов

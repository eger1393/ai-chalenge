# Отчёт по задаче: проверка GPU на SSH-хосте `superlook-gpu-dev`

## Краткое описание задачи

Найти SSH-хост `ГПУ-ДЕВ`, подключиться к нему, определить установленную
видеокарту и зафиксировать результат отдельным отчётом.

## Что проверено

- SSH-алиас: `superlook-gpu-dev`
- Удалённый hostname: `ubuntu-server`
- GPU: `NVIDIA GeForce RTX 4090`
- VRAM: `24564 MiB` (около `24 ГБ`)
- Драйвер NVIDIA: `550.144.03`
- CUDA Version: `12.4`
- Оперативная память: `31 GiB`
- Доступно RAM на момент проверки: около `29 GiB`
- Swap: `8 GiB`
- Текущее использование GPU на момент проверки: `2 MiB`
- Активных GPU-процессов на момент проверки не было

## Практический вывод

Это сильная GPU-машина для LLM-инференса. На ней разумно запускать:

- современные `7B`, `8B` и `14B` модели практически без ограничений в `Q4`,
  `Q5` и часто в `8-bit`
- современные `24B` и `32B` модели в `4-bit` / `Q4` при умеренном контексте
- `Gemma 4 31B` в `Q4` и `Gemma 4 26B A4B` в `Q4` — по официальным оценкам
  памяти это уже реальный класс для `24 ГБ VRAM`
- кодовые и reasoning-модели среднего размера, если рантайм поддерживает
  их квантизацию и формат

Пограничный класс:

- `70B` модели только в агрессивной квантизации и/или с CPU-offload
- очень длинный контекст на `32B+`, где VRAM начнёт съедать KV-cache

## Результаты проверки

- SSH-доступ к хосту подтверждён
- Параметры GPU сняты через `nvidia-smi`
- Параметры RAM сняты через `free -h`

## Ограничения и допущения

- Вывод о пригодности для конкретных LLM-моделей сделан по объёму VRAM,
  классу GPU и типичной практике запуска через `Ollama`, `LM Studio`,
  `llama.cpp`, `vLLM` и похожие рантаймы
- Фактический потолок зависит от формата модели, длины контекста, KV-cache,
  числа одновременно активных процессов и конкретного рантайма
- Установка рантайма и тестовый запуск моделей на этом сервере в рамках
  задачи не выполнялись

# Отчёт по задаче: открыть PostgreSQL stage наружу

## Статус

Готово

## Краткое описание задачи

Раскатить на stage изменение `docker-compose.yml`, которое публикует PostgreSQL наружу, чтобы к нему можно было подключаться с локального компьютера.

## Что выполнено

- На stage синхронизирован актуальный `docker-compose.yml`
- Перезапущены сервисы:
  - `postgres`
  - `postgres-mcp`
  - `knowledge-base-mcp`
  - `backend`
- PostgreSQL на stage теперь опубликован как `6502:5432`

## Проверки

- `docker compose ps` на stage:
  - `postgres` в статусе `healthy`
  - опубликован порт `0.0.0.0:6502->5432`
- На сервере сокет слушает:
  - `ss -ltn` показал `0.0.0.0:6502`
- Внешняя TCP-проверка:
  - `nc -vz 167.235.226.104 6502` — успешно
- Проверка реального подключения:
  - `PGPASSWORD=chatpass psql -h 167.235.226.104 -p 6502 -U chatuser -d chatdb -c '\conninfo'`
  - подключение успешно

## Замечания

- Во время перекладки был прерван фоновый импорт Telegram-дампа в `knowledge_base`
  - код завершения: `137`
  - при необходимости импорт нужно запустить заново
- Публикация PostgreSQL наружу повышает риск несанкционированного доступа
  - минимально стоит ограничить доступ через firewall по IP
  - текущие тестовые учётные данные небезопасно держать открытыми в публичной сети

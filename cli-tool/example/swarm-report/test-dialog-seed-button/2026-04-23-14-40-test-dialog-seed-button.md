## Краткое описание задачи

Добавить во фронтенд кнопку для запуска фиксированного тестового диалога из 10 сообщений. Кнопка должна быть доступна только в пустом диалоге и использовать текущие параметры активного диалога.

## Что реализовано

### UI

- В `frontend/src/components/chat/empty-state.tsx` добавлена кнопка `Запустить тестовый диалог`.
- Кнопка показывается только когда:
  - диалог пустой
  - не идёт загрузка истории
  - pipeline не выполняется
  - есть активный пустой диалог или хотя бы один проект, из которого можно создать новый диалог

### Оркестрация

- В `frontend/src/components/chat/chat-layout.tsx` добавлен фиксированный список из 10 пользовательских сообщений.
- В список включено сообщение `че каво, какие траблы были в Claude code?` для проверки связки `RAG + rewrite`.
- Сообщения отправляются последовательно через существующий `handleSend()`, то есть:
  - используются текущие параметры модели/диалога
  - используется текущий `contextStrategy`
  - при отсутствии диалога создаётся новый диалог через штатный flow

### Безопасная очередь

- Добавлено состояние очереди тестового диалога.
- Следующее сообщение запускается только после того, как предыдущий pipeline:
  - завершился успешно
  - был загружен обратно в conversation history
  - прошёл штатный `pipeline.reset()`
- Это исключает гонку, при которой reset предыдущего pipeline мог бы сбить следующий прогон.

### Поведение при ошибке

- Если один из прогонов падает со статусом `failed`, автосценарий останавливается и не продолжает отправлять следующие сообщения.

## Проверка

- Выполнено: `npm run build` в `frontend/`
- Результат: успешно

## Ограничения

- Зафиксированы только пользовательские сообщения; ответы по-прежнему генерируются моделью и зависят от текущих параметров диалога.
- Автосценарий не делает retry на клиенте при `failed`-шаге — это намеренно, чтобы тестовый диалог показывал реальные сбои пайплайна.

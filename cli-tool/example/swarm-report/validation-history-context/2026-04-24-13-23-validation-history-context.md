# Отчёт: validation-history-context

- Дата: `2026-04-24 13:23`
- Статус: `Исправлен`

## Описание проблемы

На этапе `validation` в пайплайне не передавался предшествующий контекст
диалога, из-за чего валидатор мог некорректно ругаться на факты, которые были
даны в прошлых сообщениях и важны для оценки текущего ответа.

## Корневая причина

- `planning` и `execution` собирались через `StepRunnerService.buildStageMessages()`
  и получали `contextMessages`.
- `validation` в обеих стратегиях (`standard` и `rag`) собирался вручную и не
  включал историю диалога вообще.

## Что исправлено

- Вынесен общий helper `buildValidationHistoryMessages()` в
  `backend/src/message-processing/services/strategies/message-processing-strategy.interface.ts`.
- `standard` validation переведён на `buildStageMessages()`:
  - теперь получает историю диалога
  - исторические сообщения явно маркируются как справочные
  - текущий запрос пользователя отдельно помечается как главный объект проверки
- `rag` validation переведён на `buildStageMessages()` по той же схеме:
  - сохраняется отдельный `RAG evidence` system message
  - добавляется исторический контекст как справка
  - приоритет проверки остаётся у текущего пользовательского сообщения
- В system/user prompt валидатора добавлены явные инструкции:
  - исторические сообщения можно использовать как справочный контекст
  - они не должны подменять текущий запрос пользователя
  - валидатор в первую очередь проверяет корректность ответа именно на текущий
    запрос

## Результаты проверки

- Выполнено: `npm run build` в `backend/`
- Результат: успешно

## Ограничения и допущения

- В рамках задачи не менялся парсер `validation`-ответа и не менялся контракт
  `VERDICT/SCORE/REASON/ISSUES`.
- История передаётся в validation как отдельные сообщения с явной маркировкой,
  а не как неразмеченная прямая копия прежнего диалога.

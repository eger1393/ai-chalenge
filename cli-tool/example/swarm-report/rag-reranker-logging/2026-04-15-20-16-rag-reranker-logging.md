# Отчёт: расширенное логирование RAG reranker

## Задача

Добавить подробные логи по пути `reranker`, чтобы повторить кейс и понять,
почему найденные фрагменты не проходят отбор.

## Что реализовано

- В `RagService` добавлен `traceId` для одного RAG-запроса
- Добавлены логи старта retrieval с параметрами запроса и ограничениями
- Добавлены логи кандидатов после vector search
- Добавлены логи итогового решения по каждому кандидату в `reranker`:
  similarity, reranker score, пороги и причина отсева
- Добавлены логи финального отбора в контекст:
  `top_k`, лимит на количество фрагментов из одного документа и ограничение по
  размеру контекстного блока
- В `RagRerankerService` добавлены сырые логи оценки каждого кандидата моделью

## Проверка

- `cd backend && npm run build`
- Stage deploy: `docker compose up -d --build --force-recreate --no-deps backend`
- `docker compose ps backend`
- HTTP smoke: `GET /api/auth/me` вернул ожидаемый `401 Unauthorized`
- Для предметной диагностики нужно повторить реальный кейс и смотреть
  `docker compose logs -f backend`

## Ограничения и допущения

- Логирование временно стало заметно подробнее и шумнее
- Логика отбора не менялась, добавлена только диагностика
- Без повтора реального пользовательского кейса новые reranker-логи пока не
  заполняются полезными данными

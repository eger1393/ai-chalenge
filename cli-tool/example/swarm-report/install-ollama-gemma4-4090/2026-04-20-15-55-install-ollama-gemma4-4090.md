# Отчёт по задаче: установка `Ollama` и запуск `gemma4:31b` на `RTX 4090`

## Краткое описание задачи

На SSH-хосте `superlook-gpu-dev` установить `Ollama`, скачать модель
`gemma4:31b` и подтвердить практическим запуском, что модель реально работает
на `NVIDIA GeForce RTX 4090`.

## Контекст хоста

- SSH-алиас: `superlook-gpu-dev`
- hostname: `ubuntu-server`
- ОС: `Ubuntu 22.04.5 LTS`
- GPU: `NVIDIA GeForce RTX 4090`
- VRAM: `24564 MiB`
- RAM: около `31 GiB`

## Что обнаружено до установки

Корневой раздел был заполнен:

- `/`: `929G`, занято `885G`, свободно `0`
- `docker system df` показывал:
  - образы: `518.1GB`
  - build cache: `259.5GB`
- `journalctl --disk-usage`: `3.9G`

## Что сделано

Перед установкой очищено место:

- `docker builder prune -af`
  Освободил `743GB`
- `journalctl --vacuum-size=500M`
  Освободил около `3.5G`
- `apt-get clean`

После этого корневой раздел вернулся в рабочее состояние:

- `/`: свободно `242G` до загрузки модели

Далее выполнено:

- установлен `Ollama` официальным Linux-инсталлятором
- подтверждён запущенный `systemd`-сервис `ollama`
- скачана модель `gemma4:31b`
- выполнен реальный запрос к локальному API `Ollama`

## Результат установки

- `Ollama` установлен
- версия `Ollama`: `0.21.0`
- сервис `ollama.service`: `active`
- локальный API отвечает на `127.0.0.1:11434`
- модель `gemma4:31b` присутствует в `ollama list`

## Результат тестового запуска

Тестовый запрос:

`Коротко, в трёх пунктах объясни, что такое RAG в LLM-приложениях.`

Модель ответила успешно через `Ollama API`.

Фактические метрики первого запуска:

- `load_duration`: около `5.77s`
- `total_duration`: около `31.05s`
- `eval_count`: `604`
- `eval_duration`: около `24.94s`
- ориентировочная скорость генерации: около `24.2 токена/с`

Состояние после загрузки модели:

- `ollama ps`:
  - модель: `gemma4:31b`
  - загруженный размер: `27 GB`
  - processor: `13%/87% CPU/GPU`
  - context: `32768`
- `nvidia-smi` после загрузки:
  - VRAM used: `23702 MiB`

## Практический вывод

`gemma4:31b` на этой `RTX 4090` работает и реально использует GPU.

При этом модель почти упирается в потолок `24 ГБ VRAM`:

- после загрузки остаётся очень небольшой запас видеопамяти
- для стандартного рабочего контекста запуск нормальный
- для очень длинного контекста запас уже тесный, потому что дополнительную
  память будет съедать `KV-cache`

То есть как основной локальный кандидат модель подтверждена, но это уже
верхняя комфортная граница для одной `RTX 4090 24 ГБ`.

## Состояние диска после выполнения

- `/`: `929G`, занято `663G`, свободно `219G`, использование `76%`

## Ограничения

- Проверка выполнена на одном практическом запросе
- Отдельный стресс-тест длинного контекста, параллельных запросов и
  многократной повторной загрузки не проводился
- Сервис слушает только `127.0.0.1:11434`; внешняя публикация API не
  настраивалась
